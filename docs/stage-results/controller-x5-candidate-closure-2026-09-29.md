## What a new candidate needs

The next development candidate must use a newly authored, prospectively
frozen corpus. Public issues and actor source must contain realistic competing
causes without revealing the reference repair. An independent protected
reference, plausible wrong repair, isolation check and public check must pass
before any provider call. Include ordinary-worker and missing-decision
controls. Keep these development cases separate from the sealed X6 reserve.

Before comparing A with S, calibrate a separate development slice to confirm
that the baseline has meaningful failure or partial-progress headroom. Do not
select or rewrite paired cases after seeing A outcomes. Freeze case selection,
arm order, role profiles, worker tool surface, acceptance rubric, report
provenance, analysis and budget before the paired run. Score host functional
acceptance, worker-produced evidence, honest completion claims, critical
errors, cost and latency separately. Host-run probes must never be presented
as worker-run probes. Record actual served model and mark unsupported served
effort unknown.

Set a prospective development stop gate: require a measured benefit over S
on cases where S does not saturate, no worsening of critical errors or false
success, and a defensible cost and latency tradeoff. If that gate fails,
retain B0 without accessing reserved cases. Any new paid campaign needs its
own dated cost notice and approval as required by the host and project rules.
Only a newly qualified candidate may propose a new X6 contract, followed by
independent X7 adjudication and conditional X8 packaging.

## What v4 established

The v4 payment assessment settled one `claude-sonnet-5` call at USD
0.050811401 with no unresolved charge. Its public packet cited the issue
heading, one public assertion and the incident trace. It did not cite the
issue body that states the authorised outcome, constraints and competing
causes. The returned worker fields were `frame_confidence=uncertain` and
`failure_cause=identity`; N3 stopped at `unresolved_frame` before a routing
decision. The rigour result named an investigation, but no Controller
admission was observed. Five later screen tasks and all pilot episodes
remained unused. These are observations, not evidence of an uplift or a
counterfactual decision.

The packet omission is a concrete design defect: the shared public
assessment prompt requires each field to cite supplied lines. The prompt
also left the worker meanings of frame confidence and failure cause
unstated. Tenant identity in the incident could therefore be confused with
worker-host identity. The observed output cannot establish which omission
caused the stop.

## Prospective v5 change

V5 reuses the four independently audited v4 actor and protected oracle byte
sets, plus unchanged X3 N01-D1 and C08-D2 controls. This is a development
retest of those cases, not independent replication. It uses fresh single-use
N1 roots and a new manifest; no v4 root is replayed.

The new packet rule cites **every nonblank issue line** and every public
assertion, plus every uniquely citable, nonstructural incident-trace line.
This rule is the same for all six tasks and exposes the actual task mandate,
constraints and competing explanations. It rejects duplicate or ambiguous
quotes and the 32-citation limit before a provider call. The public sources
remain bounded by the existing collector, with protected oracles outside
the actor package.

The shared prompt now distinguishes worker execution failure from the
domain defect, and task-frame clarity from uncertainty about its causal
explanation. It also distinguishes an executable but incomplete public
check from qualitative verification. These are field definitions; the N3
selector, Controller routing thresholds, task labels, acceptance oracle and
first-miss gate are unchanged. The prompt source change must pass the full
offline harness and reach `dist/` through the checked builder.

V5 calls the production N1 routing-decision freeze after a successful N3
selection. A screen pass requires a **durable** automatic decision on the
root, not merely a local recommendation. An N3 stop still blocks the next
assessment. The stopped result includes the worker frame/failure fields and
the independent rigour recommendation for diagnosis only; neither counts
as an admission.

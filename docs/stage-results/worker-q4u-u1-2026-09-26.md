# Q4U U1: opt-in changed-output acceptance

Date: 2026-09-26 UTC. Status: **complete, provider-free**. B0 dispatch,
the Controller and the sealed Q4T campaigns are unchanged.

Version-1 command contracts may now specify `require_changed_output: true`.
`tools/acceptance.py` freezes the required-output snapshot inside the
contract at admission. At verification it records a second snapshot *before*
running the command. A successful command with unchanged outputs is a
qualified failure, so `TaskExecutor` can use its existing bounded repair
ladder. An actual byte change or new required output can pass. The verifier
blocks if its command changes the required outputs, preventing test-created
files from being mistaken for worker edits on this or a later attempt. The
evidence validator re-derives the change decision from sealed snapshots;
blocked evidence is reused without rerunning the command.

The option is absent by default and restricted to command contracts. This
preserves correct no-edit work, including the earlier N5 control task. It
checks that a change occurred, **not** that the new behaviour is correct; the
public command must still cover the task requirements. U1 does not infer the
option from issue wording and does not change any routing trigger.

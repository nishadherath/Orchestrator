# Q4U U0: S05 no-op acceptance diagnosis

Date: 2026-09-26 UTC. Status: **complete, provider-free**. The sealed
[Q4T S3 campaign](../../test/results/2026-09-26-worker-q4t-s3-run/campaign.json)
is development evidence; no paid episode was replayed or altered.

S05 asks for bounded memory under repeated `seekable.peek()` and truth checks.
Its public check makes five peeks and verifies iteration order, but never
measures retained memory. Both Sonnet-low S05 roots had a passing public
verification and were marked accepted with **zero changed source paths**.
Their worker reports said the existing implementation needed no edit; one
claimed completion and was marked an unsupported completion by the quality
grader, while the other reported a partial result. Independent hidden checks
rejected both at executable score 45 and quality 40/50. The diagnostic
Sonnet-medium arm changed `more_itertools/more.py`, passed hidden acceptance
and scored 100 executable / 90 quality.

The source confirms the mechanism: `acceptance.verify` previously passed a
command contract when its command exited zero, required outputs existed and
protected paths were intact. It did not compare those outputs with their
admission bytes. `TaskExecutor` accepted any qualified pass. Thus a weak
public smoke test could accept an unchanged implementation. A focused offline
reproduction was red before the opt-in contract field was implemented: four
new tests errored because `require_changed_output` was unsupported.

This is not evidence that medium effort generally solves resource tasks.
S05's observed medium arm was a separate fresh run; an unrun low-then-medium
continuation has no measured outcome or cost. The trigger's current
cross-component rule missed this single-module task, but one task cannot
justify a replacement classifier. The existing N4 R-series generator and
oracle inputs were inspected during this diagnosis, so that set is not a
blind reserve for Q4U candidate tuning or confirmation. Q4U needs newly
frozen, disjoint reserved cases.

Next: U1 adds an optional byte-change requirement to command acceptance.
U2 must evaluate task-sensitive routing separately, using public evidence
only and retaining B0 until a prospective comparison qualifies a candidate.
